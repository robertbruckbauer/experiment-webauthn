== Frontend commands

From `/tmp/workspace/robertbruckbauer/experiment-webauthn/frontend`:

* `pnpm install`
* `pnpm build`
* `pnpm test`
* `pnpm test:e2e`
* `pnpm lint`
* `pnpm dev`

The Vite dev server proxies `/api` requests to `http://localhost:8080`.
The frontend uses `keycloak-js` (Authorization Code + PKCE S256), refreshes tokens, and always calls the backend with the latest access token.
WebAuthn/passkey registration and verification are handled by Keycloak only.

Required frontend env vars:

* `VITE_KEYCLOAK_URL` (e.g. `http://localhost:8081`)
* `VITE_KEYCLOAK_REALM` (e.g. `webauthn`)
* `VITE_KEYCLOAK_CLIENT_ID` (e.g. `frontend-spa`)

Required backend env vars:

* `OAUTH2_ISSUER_URI` (e.g. `http://localhost:8081/realms/webauthn`)
* `OAUTH2_AUDIENCE` (defaults to `backend-api`)
* `OAUTH2_CLIENT_ID` (defaults to `frontend-spa`)
* `FRONTEND_ORIGIN` (defaults to `http://localhost:5173`)

== Keycloak passkey architecture

* React only uses `keycloak-js` (`keycloak.login()` and Keycloak enrollment redirect).
* React does not call browser WebAuthn APIs directly (`navigator.credentials.create/get` are not used).
* Keycloak owns challenge generation, credential storage, registration, and verification.
* Spring Boot is OAuth2 Resource Server only (JWT validation + business APIs).
* The SPA is e-mail-first: user enters e-mail, then registers passkey or logs in with that e-mail hint.

== Keycloak realm/client/passkey setup

The included import (`keycloak/realm-export.json`) provides a baseline realm/client setup:

* Realm: `webauthn`
* SPA client: `frontend-spa` (public, standard flow, PKCE S256, redirect URI/web origin for `http://localhost:5173`)
* API audience mapper: `backend-api-audience`
* WebAuthn passwordless policy fields (RP entity name/RP ID/origin aligned to local setup)
* Required action providers for WebAuthn registration
* Realm registration configured to use e-mail as username

In Keycloak Admin UI, configure:

1. `Realm settings -> Authentication -> WebAuthn Passwordless Policy`
   * RP ID: `localhost`
   * Origin: `http://localhost:5173`
   * User verification: `required`
   * Attestation conveyance: `none`
   * Resident key / discoverable credential: `Yes`
2. `Authentication -> Flows`
   * Create/adjust browser flow to include **WebAuthn Passwordless Authenticator**
3. `Authentication -> Required actions`
   * Enable **WebAuthn Register Passwordless**
4. Assign required action to users (or allow enrollment from account console).

Passkey enrollment from React is done via Keycloak redirect (required action), not custom backend/frontend WebAuthn endpoints.

== Docker Compose commands

From `/tmp/workspace/robertbruckbauer/experiment-webauthn`:

* `docker compose up`
* `docker compose down`

Compose starts:

* Keycloak on `http://localhost:8081` with realm import from `keycloak/realm-export.json`
* Backend on `http://localhost:8080`
* Frontend on `http://localhost:5173`

Default demo user:

* username: `user`
* password: `user`

Use the UI buttons:

* Enter e-mail first.
* **Register with e-mail + passkey**: starts Keycloak registration/enrollment flow with `webauthn-register-passwordless`.
* **Login with Keycloak**: starts login using the entered e-mail as login hint.
* **Logout and remove passkey**: removes `webauthn` / `webauthn-passwordless` credentials via Keycloak account API, then logs out.
* Home page shows login state and credential details (subject, preferred username, e-mail, roles, scopes) while logged in.
